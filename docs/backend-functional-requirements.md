# 백엔드 기능 요구사항 명세

상태: 백엔드 요구사항 초안 · 구현 완료를 의미하지 않음

범위: 백엔드 A·B·C의 기능과 REST·STOMP 연동 계약. 프런트엔드 구현 및 담당 배분은 제외한다.

## 1. 기준 및 담당 확인

2026-09-17 사용자 기술 결정과 [최종 백엔드 분배안](../DB%20관리%20시스템%20백엔트%20파트분배_최종.html), [백엔드 업무 분배](backend-responsibilities.md)를 기준으로 작성했다.
이전 `Branches DB/Branches DB/파트별 체크리스트.html`과 충돌하는 담당은 최종 분배안을 따른다. 기존 문서의 언어·프레임워크 및 Redis 전달 방식 미정 표기는 아래 사용자 결정으로 대체한다.

| 파트 | 확인된 담당 | 책임 범위 |
| --- | --- | --- |
| A | 팀장 | MariaDB 연결·수집, 메트릭 저장·조회, 수집 이벤트 발행 |
| B | 팀원 1 | 인증·권한, 대상 DB 관리, 접속 정보 암호화, 감사 로그 |
| C | 팀원 2 | 실시간 전송, 위험도·수집 중단 판단, 장애·알림·이력 |

각 요구사항의 주관은 백엔드 구현 책임이다. 연계 파트는 해당 기능에 필요한 설정·데이터·인증을 제공한다.
로그아웃·재연결·실패 처리 등은 기존 기능을 검수 가능하게 구체화한 초안이다. 수치·정책 미정 항목은 마지막 절에 분리했다.

## 2. 확정 기술 및 연동 조건

| 항목 | 확정 내용 |
| --- | --- |
| 백엔드 | Java + Spring Boot |
| 시스템 DB | PostgreSQL. 사용자·대상 DB 설정·메트릭·정책·장애·감사 기록 등 시스템 데이터를 저장 |
| 모니터링 대상 | MariaDB. 접속하여 상태·성능 지표를 수집 |
| 내부 이벤트 | Redis Streams |
| 실시간 클라이언트 연동 | WebSocket + STOMP |
| 인증 | JWT 기반. Access Token은 프런트 메모리에 보관하고 REST는 Bearer 헤더, STOMP는 CONNECT 헤더로 전달 |
| Refresh Token | HttpOnly·Secure 쿠키로 전달 |
| REST 계약 | springdoc-openapi로 OpenAPI 명세 제공, Swagger UI로 확인. REST 연동의 공통 기준 |
| STOMP 계약 | REST OpenAPI와 별도 문서로 목적지·메시지·인증·오류·재연결 규칙 제공 |

## 3. 기능 요구사항

아래의 ‘필수’는 기존 백엔드 MVP 요구사항 초안을 기준으로 한 분류다. 세부 정책과 수치는 추가 합의 대상이며, 구현 완료를 의미하지 않는다. 주관·연계는 백엔드 파트 분배를 나타낸다. 기존 요구사항 ID는 유지한다.

**A. 모니터링 대상 및 수집 관리**

| ID | 기능 | 요구사항 | 구분 | 주관 | 연계 |
| --- | --- | --- | --- | --- | --- |
| DB-01 | DB 대상 등록·조회·수정·삭제 | Admin이 대상 MariaDB 접속 정보와 식별 정보를 등록·수정·삭제하고, 인증된 사용자가 목록·상세를 조회한다. | 필수 | B | A |
| DB-03 | 연결 확인·메타데이터 조회 | 대상 DB 연결·Ping 확인과 버전 등 기본 메타데이터 조회를 제공한다. | 필수 | A | B |

## 4. 백엔드 파트 간 연결

| 연결 | 제공 기능 | 수신 측 책임 |
| --- | --- | --- |
| B → A | 대상 DB 설정·접속 정보 접근, 공통 인증·권한 | A가 등록·변경·삭제에 맞춰 수집 대상을 관리하고 조회 API에 인증 적용 |
| A → C | MetricCollectedEvent, 시도·성공 시각·실패 구분 | C가 실시간 전송·위험도 판단·수집 중단 감지 |
| B → C | 토큰 검증·사용자·권한 | C가 STOMP 연결·구독과 정책·이력 API에 적용 |
| C → B | 정책 변경 등 감사 대상 행위 | B가 공통 감사 기록으로 저장·조회 |


## 5. 통합 완료 기준

1. 일반 사용자와 Admin으로 로그인하여 REST 권한 차이를 확인한다. 서버의 토큰 응답·헤더 검증·쿠키 속성을 확인한다.
2. Admin이 MariaDB를 등록하면 A가 연결·지표 수집·PostgreSQL 저장·Redis Streams 발행을 수행한다.
3. 인증된 STOMP 구독자가 지표를 수신하며 기간별 REST 조회로 같은 대상의 과거 지표를 확인한다.
4. 임계치 초과가 설정 시간 동안 지속되면 C가 위험도와 OPEN 사건을 생성하고 외부 알림을 발송한다.
5. 같은 장애가 반복되어도 사건·알림이 합의한 중복 억제 규칙을 지킨다. 정상화하면 RESOLVED와 복구 시각을 확인한다.
6. 대상 DB 접속 실패와 수집기 중단을 각각 발생시켜 실제 0·실패·미수집을 구분하는지 확인한다.
7. C 및 클라이언트 재시작 후 이벤트 복구·최신 상태 조회·재구독과 중복 억제를 확인한다.
8. 미인증 요청·User 변경 요청을 거부하고 DB·권한·정책 변경의 감사 기록을 확인한다.

## 6. 추가 합의가 필요한 사항

- 수집 주기, QPS 계산 구간, Slow Query 지표의 정의·단위, 조회 최대 기간, 메트릭 보관 기간.
- 위험도 4단계 명칭·임계치·지속 시간·복구 조건, 수집기 생존 신호와 타임아웃 기준.
- DB 등록 시 연결 실패 허용 여부, 대상 수정 반영 시점, 삭제 후 과거 메트릭·장애 이력 보존 여부.
- Access/Refresh 유효기간, Refresh 회전·폐기, 로그아웃 시 기존 Access 효력, 연결 중 토큰 만료 처리. 쿠키 SameSite·Path·도메인 및 배포 구조에 맞춘 CORS·CSRF 정책.
- 최초 Admin 생성·권한 변경 절차, 감사 기록 열람 권한.
- Redis Stream 키·보관 기간·Consumer Group·ACK 시점·재처리 범위, PostgreSQL 저장과 발행 사이 실패 시 복구 방식. 실시간 전송과 위험도 판단을 독립 소비자로 둘 경우 두 처리에 모두 이벤트가 도달하도록 구성한다.
- 장애 동일성 기준, 알림 쿨타임·실패 재시도·복구 알림 여부, 사용할 메신저·지원 모바일 환경·수신처 관리 권한.
- 공통 Spring 설정·DB 마이그레이션·OpenAPI 설정·배포 담당자.

AI 일일 보고서·위험 쿼리 분석은 이전 체크리스트의 Phase 2 후보이다. 최종 MVP 분배안에는 없어 이번 MVP 요구사항과 확정 파트 배분에 포함하지 않는다.
